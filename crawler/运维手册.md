# M-1 采集器运维手册（验收前置交付物）

**版本 v0.1 · 2026-08-07 · 适用：`crawler/` 工程 · 面向项目方自运维**
**铁规矩复述**：密钥只在 `.env`；遇验证码立即停手绝不绕过；本手册任何操作不得修改 UA 与间隔参数。

## 故障 1：日志出现 `302 ... LimitingCaptcha`（验证码墙）

- **含义**：触发木鸟 WAF 日频限。采集器已自动停手（合规设计）。
- **处置**：当天**不要再跑**。次日 20:00 定时任务会自然恢复。若连续 2 天触发：把 `.env` 的 `REQUEST_INTERVAL` 调大到 `5`，并检查是否有人同日重复全量跑。
- **禁止**：禁止换 IP、禁止打码平台、禁止模拟验证码通过——违反即整单打回。

## 故障 2：日志 `robots.txt 获取失败 http=xxx，中止本次运行`

- **含义**：robots 没抓到（网络问题或对方 WAF）。
- **处置**：手动验证——浏览器打开 `https://www.muniao.com/robots.txt`。能打开→等 1 小时重跑 `python run_track.py --limit 5` 试；打不开→对方在封，当天停跑。
- **留档位置**：`logs/robots_YYYYMMDD.txt` 看当天抓到的原文。

## 故障 3：日志 `robots 新增禁止路径 /dalian/ 或 /room/，中止运行`

- **含义**：木鸟改了 robots 协议，继续采集将不合规。
- **处置**：**不要改代码绕过**。立即上报项目方，由项目方决策（降级到飞猪/官方 API 或停止该平台）。

## 故障 4：追踪层快照数明显变少（告警"数据量骤降"）

- **先查**：`logs/crawler.log` 当天是否有大量 `HTTP 302`——是→按故障 1 处理。
- **再查**：抽查 1 间房源——`python run_track.py --refs <某个roomId>`，看返回字段。若 price/rating 全 None → 对方改了页面结构，按故障 5 处理。

## 故障 5：详情页字段解析全 None（对方改版）

- **验证**：`python tests/test_parse.py` 若也挂 → 留档样本是旧的，先抓新样本：
  浏览器打开任一 `https://www.muniao.com/room/<id>.html`，另存为 HTML 覆盖 `首日复测/留档/木鸟_详情页样本.html`，再跑单测看哪项挂。
- **修解析**：`muniao_crawler/parse.py` 顶部第 14–21 行是全部正则（RE_PRICE 价格 / RE_RATING 评分 / RE_REVIEWS 点评 / RE_MAP 坐标区域）。对照新样本改对应正则，改完必须 `python tests/test_parse.py` 全绿才算修好。

## 故障 6：发现层 `unique_rooms` 连续两次运行大幅减少

- **含义**：翻页 URL 规则失效（对方改参数）。
- **处置**：浏览器打开 `https://www.muniao.com/dalian/` 点第 2 页，看地址栏新规律，改 `config.json` 的 `list_page_n`（注意 `null-…-1.html` 变体是 robots 禁止的，不能用）。日期规则"明日/后日"在 `discover.py` 的 `run()` 开头（d1/d2 两行）。

## 故障 7：收不到告警（飞书/邮件静默）

- **心跳测试**：删除 `data/state.json` 后运行任意采集入口，会强制发一次心跳。
- **飞书没收到**：检查 `.env` 的 `FEISHU_WEBHOOK_URL` 是否填错；把该 URL 粘到浏览器应返回 JSON 报错信息（GET 不允许属正常，401/400 说明 URL 有效）。
- **邮件没收到**：`SMTP_PORT` 默认 465（SSL）。若邮箱服务商要求 587（STARTTLS），改 `alerts.py` 里 `SMTP_SSL` 为 `SMTP` + `starttls()`（`_email` 函数内，约第 40 行）。

## 故障 8：数据库锁 `database is locked`

- **含义**：两个采集进程同时跑了。
- **处置**：`data/` 下无多实例锁（v0.1 约定单实例）。检查 cron 是否配重、是否有上次进程残留（Windows 任务管理器搜 python，结束之）。

## 故障 9：快照日期缺失某天

- **查询**：`sqlite3 data/muniao.db "SELECT * FROM crawl_log WHERE layer='track' ORDER BY id DESC LIMIT 10"`——没行就是当天没跑（机器关机/cron 失效）。
- **补跑**：`python run_track.py` 当日补跑即可；快照幂等，同日重跑覆盖不重复。

## 故障 10：price_changed 恒为 0 或恒为 1

- **恒 0**：正常——价格本就稳定；异常情况是全库无一条历史快照（库被删过，`data/muniao.db` 重建首日全 0 属正常）。
- **恒 1**：检查是否每天采到不同币种/单位（解析错位），按故障 5 流程验证 price 字段。

## 日常巡检（每周 1 次，5 分钟）

1. `logs/crawler.log` 最近 7 天无连续 ERROR
2. `sqlite3 data/muniao.db "SELECT COUNT(*), snapshot_date FROM snapshot_price GROUP BY snapshot_date ORDER BY snapshot_date DESC LIMIT 7"`——每天行数稳定
3. `logs/robots_*.txt` 有最新日期的留档
